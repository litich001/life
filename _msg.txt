Make the motion fast enough to actually see

The periods were the bug, not the CSS. 180s per revolution is 2 degrees a
second: in a five-second visit the rose turns 10 degrees and reads as a still
image. Everything else meant to look alive was in the same range -- 74s bezel,
34s wash, 30s band drift, 8.5s halo.

Now: rose 32s per revolution (11.2 deg/s, caught in peripheral vision), bezel 14s
the other way (25.7 deg/s), wash 15s, band drift 12s and 16s in opposite
directions, halo 4.2s.

Two more faults found while verifying, both from editing around here rather than
in it:

  - A duplicate block. The new drift/roseSpin rules were inserted while the old
    ones stayed later in the file, so the later copy won on source order and the
    rose kept turning at 180s no matter what the new rule said. Duplicated
    keyframes are silent; nothing warns.

  - @keyframes wash had been deleted by an earlier edit that replaced the block
    it lived in. The name stayed declared, so it computed as animation-name:
    wash with transform: none -- the hero wash was doing nothing at all while
    still looking, in a computed style, like it was running.

Verified by driving currentTime through the Web Animations API and reading the
resulting transform back, rather than trusting the declared duration:
  .rose__g     0ms -> 0deg, 1000ms -> 11.2deg, 3000ms -> 33.7deg
  .rose__ring  0ms -> 0deg, 1000ms -> -25.7deg, 3000ms -> -77.1deg
  wash / halo / drift all resolve to real translate and scale matrices again

getAnimations() is also how to tell "the CSS is broken" from "this tab is
hidden": all 43 animations report playState running while document.timeline
stays pinned at 0 and visibilityState is hidden. Same observable signature as a
dead stylesheet, so check playState before rewriting anything.
